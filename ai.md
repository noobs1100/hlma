# HLMA Expo — Project Summary (AI)

**Project**: hlma-expo

**Purpose**: Mobile Expo app (React Native + Expo Router) that integrates with a Hono + Better Auth backend for cookie-based authentication. The app supports email/password sign up & sign in, session restore, protected routes, and social auth (via Better Auth + Expo helpers).

**Quick facts**

- Frameworks: Expo, React Native, Expo Router
- Auth: Better Auth (cookie-based) with the Expo plugin
- Secure storage: `expo-secure-store` (used by Better Auth expo client)
- Backend base URL: configured via `EXPO_PUBLIC_API_URL`

**Important env**

- `EXPO_PUBLIC_API_URL` — base URL of your backend (e.g. `http://localhost:3000`). The app constructs auth base at `/api/auth`.

Example `.env` (root):

```
EXPO_PUBLIC_API_URL=http://localhost:3000
```

**App scheme**

- `app.json` contains `scheme: "hlmaexpo"` — used by the Better Auth Expo plugin for deep linking callbacks.

**Auth endpoints (backend)**

- Sign up (email): POST /api/auth/sign-up/email
- Sign in (email): POST /api/auth/sign-in/email
- Session check: GET /session
- Sign out: provided by Better Auth (use `signOut` client call)

**Where auth code lives (key files)**

- `lib/auth-client.ts` — creates the Better Auth client with the `@better-auth/expo` plugin and `expo-secure-store`.
- `lib/auth-helpers.ts` — small API helper wrappers (signIn, signUp, restoreSession, signOut) and validators.
- `providers/auth-provider.tsx` — React context that exposes `session`, `user`, `isLoading`, `isAuthenticated`, `refreshSession`, `logout`. Restores/refreshes session and listens for app resume.
- `components/AuthScreen.tsx` — small presentational wrapper for the sign-in / sign-up screens (loading, error, layout).
- `app/sign-in.tsx` & `app/sign-up.tsx` — screens wired to the auth helpers and the `AuthProvider` context.
- `app/index.tsx` — loading / session-restore screen that redirects the user on startup based on session state.
- `app/(tabs)/_layout.tsx` — protected tab layout; redirects unauthenticated users to `/sign-in`.
- `app/(tabs)/three.tsx` — profile tab where a logout action is available.

**How cookies & sessions are handled in Expo**

- Browsers persist cookies automatically, but native apps don't share browser cookie storage.
- The Better Auth Expo plugin stores session cookies and session metadata securely using `expo-secure-store` (or a provided storage adapter). These stored cookies are attached to outgoing requests by the client plugin.
- The project uses the `expoClient` from `@better-auth/expo/client` in `lib/auth-client.ts` with `storage: SecureStore` so sessions survive app restarts.
- To detect expired sessions quickly, the `AuthProvider` triggers a `refetch()` when the app becomes active.
